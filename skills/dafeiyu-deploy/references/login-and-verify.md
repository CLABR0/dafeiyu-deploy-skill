# 登录、启用和验收

## 一轮内完成

1. 启动隔离 DSH2，脚本按进程路径、回环端口、抖音数据目录三项核对目标；不要假定端口固定。重新启动后也重新发现。使用工作区安装根目录时仍通过其 `Start-DSH2.cmd`。
2. 助手先确认 DSH 账号登录与模型，QQ 和抖音可以先出码再等待用户分别扫码；只保留仍有效的一张同平台码，不要一边让用户扫一边刷新。核验失败优先检查程序真实窗口和本地错误。
3. 回来先核验登录，再补齐模块和设置；一次性汇报已装、已登录、待用户操作、未测功能。不要因等待用户而写「已完成」。

## 助手什么时候要提示用户

这是给调用 Skill 的助手执行的提示清单，不是让用户自己找文档。先查实际状态，再把**当前能做的人工动作**直接发给用户：每项写清楚平台、点哪个窗口或菜单、用哪个账号，以及完成后回什么。只列触发的行；无阻塞的平台继续配置，不等另一平台。两张有效码都准备好时可以一起发，分别标明平台；如果还缺网关或客户端，先提示前置步骤，别提前出会过期的码。

| 检查结果 | 助手应该发给用户的提示 | 用户完成后助手接着做 |
| --- | --- | --- |
| DSH2 显示欢迎/登录，默认 DeepSeek 账户模型还不可用 | 「请在这次打开的 DSH2 欢迎页点登录，在官方窗口完成账号登录或手机确认。完成后回『DSH 已登录』。」只有官方窗口确实出现二维码时才展示，不承诺所有账号都能扫码。 | 检查同一 DSH2 实例并运行 `ModelProbe`；不要把客户端已登录当成模型调用成功。 |
| 机器没有官方 QQ 客户端，助手也未能完成官方安装 | 「请从[腾讯 QQ Windows 官网](https://im.qq.com/pcqq/)安装并打开 QQ，先不要退出其他账号。完成后回『QQ 已打开』。」如果只是安装窗口等本人同意条款，就指出当前窗口，不让用户再下载。 | 复查客户端和正确的机器人登录窗口。 |
| Aurabot 找不到可用网关，或 SnowLuma 尚未获用户同意 | 「QQ 客户端扫码只能登录 QQ；Aurabot 还需要网关。请在自己的电脑按 [SnowLuma 官方指引](https://snowluma.github.io/zh/docs/guide/introduction)安装/启动，并在其窗口自行阅读处理协议；如果你已有 OneBot v11，可直接用它。准备好后回『QQ 网关已就绪』。」 | 复查 Aurabot 的「连接」页，检查实际 OneBot 状态。若连接方式需要地址或令牌，请让用户在该页本地填写；不在聊天里索要。 |
| 有可用网关，但机器人 QQ 未登录 | 「请用**机器人 QQ**在手机 QQ 扫下面标为『QQ 登录』的官方二维码，并在手机上确认。扫完回『QQ 已扫』。」截图不可用时，指出当前官方 QQ 登录窗口，让用户直接扫窗口上的码。 | 验证 OneBot 已连接且机器人已登录；仅在两个账号已正确配置后执行 `QQFinish`。 |
| 机器人号和主人号未配置，或无法从已确认设置判断两者 | 「请在 Aurabot 连接/账号设置里确认哪个是机器人 QQ、哪个是你的主人 QQ（必须是两个不同账号）。填好后回『QQ 身份已确认』。」不需要用户提供密码或退出已有账号。 | 检查两个身份都已配置，继续绑定；仅在主人私聊验证工具权限。 |
| 抖音未登录，有本轮新码 | 「请用手机抖音扫这张『抖音登录』二维码，在手机上点确认，完成后回『抖音已扫』。」 | 轮询 `DouyinPoll`，等 `loggedIn=true`，不要重建浏览器会话。 |
| 抖音没有新码、验证码界面出现，或扫码后等待确认 | 「我已打开插件使用的抖音登录窗口。请在那个窗口扫码；如果页面要求短信/验证码或手机确认，请在原窗口完成。看到登录成功后回『抖音已登录』。」窗口没打开时明确说明具体错误；没有 Chrome 或 Edge 且无法自动安装时，指出缺的是可用浏览器。 | 按实际窗口重新核查；如码已过期，停止等旧码再刷新一次；不让用户把验证码发到聊天。 |
| 用户要求绑定转发/自动回复对象，但主人抖音账号还未确认 | 「请确认哪个抖音账号是你，要用它收视频。告诉我已核对的昵称；如果有同名，请在原会话确认对方身份。」 | 只绑定已核实对象，保留原名单和限额；未确认就不启用发送。 |
| 用户明确选择 OpenCode Go 等第三方模型，但缺凭据或授权 | 「请在 DSH2 的模型/供应商设置里登录该供应商或填写你自己的密钥，不要把密钥贴到这里。保存后回『模型已配置』。」默认账户模型能用且用户没要求第三方时跳过。 | 检查桌面与后台都可调用，调用不通就保持自动回复关闭，不悄悄换成模板回复。 |

遇到平台要求本人确认、短信、验证码或协议时，只指出实际出现的窗口和操作。看不到官方二维码时就说明没有可展示的码，并指出可由用户直接操作的窗口；不要用截图中的过期码、群码或自己生成的码充数。收到「好了」后先验证、再推进；仍失败时只提示真正剩下的一步。最终区分「已验证」「待本人操作」「未实测」。

## QQ / Aurabot

- 使用已有且用户已同意协议的 SnowLuma，或现有 OneBot v11。包不含网关、个人 QQ 安装包或协议同意状态。新机器缺 QQ 客户端或网关时，走 [腾讯 QQ Windows 官网](https://im.qq.com/pcqq/) 和 [SnowLuma 官方文档](https://snowluma.github.io/zh/docs/guide/introduction)；如必须手动安装/同意，助手把人机交接集中在一起，不代替用户接受条款，也不自动部署 SnowLuma。
- 机器人号和主人号必须是不同 QQ 号。能从现有官方客户端或用户已确认的配置读到就自动填；若两者无法区分，只询问最少的必要信息。启动已安装并同意过协议的网关，用 Aurabot「连接」页接入确认过的机器人号，不碰其它登录进程。
- 用官方 QQ 客户端的机器人登录窗口出码。用窗口截图出示当前真正的登录码（不是软件社区群二维码）；用户在手机 QQ 扫码。扫码后检查 `GET /aurabot/api/state` 中 OneBot 已连接、机器人登录核对通过；两个号码均已配置后，运行 `scripts/login.ps1 -Action QQFinish`。
- 现有外部 OneBot 地址或密钥让用户在其本机设置界面输入；不要向聊天发送、保存进 Skill 或抄到日志里。

## 抖音

- 执行 `scripts/login.ps1 -Action DouyinQR -Root <目录>`。返回 `scan-douyin` 时向用户显示 `qrPath` 的 PNG；这是本地临时文件，不上传、不共享给第三方。收到扫码通知后执行 `DouyinPoll`，继续直到 `loggedIn=true` 或明确超时。
- 返回 `already-logged-in` 不重复扫码。若没有本轮新码，执行 `DouyinBrowser` 打开原插件的官方登录页，在界面出示二维码。需要短信或 CAPTCHA 时交给用户在原窗口处理，不改换一个没登录的通用浏览器。
- 核实「主人」抖音昵称后才能设为转发对象和白名单，不按昵称前缀猜人。默认安装不主动跑回复、转发或发布，以免扫完码就回复旧消息。用户要求恢复自动回复且确认联系人后，使用 `EnableReplies -DouyinOwnerNick <已核实昵称>`；只有明确要求陌生人也自动回才加 `-IncludeStrangers`，原限额每人每天 1 条、总计 5 条。不要把名单清空，或靠手动发试验私信验收。

## 模型和验收

- 默认用 DSH 官方账户模型，缺登录就走 DSH 官方登录。用户明确选择 OpenCode Go 等第三方供应商时，分别核对 desktop 和 headless 的注册、鉴权及调用，不让慢回出现 `NO_ADAPTER`。本仓库不含个人密钥。
- `ModelProbe` 可用已注册模型做一次不发私信的连接检查。检查 `Status` 的 persona、seenBridge、QQ 抖音工具、私信 `all-model` / `resolve-before-reply/plain-text` / `same-chat-verified-video`。私信原文不进跨平台记忆是设计约束。
- 用主人私聊测试入口和只读命令检查推荐/搜索/看片；自动发消息不作为默认验收。视频没取到内容就说明，语音转写不代表分析了画面。
- 创作工具验收以加载和无副作用预检为准。草稿、提交回执与作品公开可见不是同一件事。
